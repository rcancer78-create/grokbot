# grokbot

Локальный HTTP-адаптер сессии Grok Bot с частичной совместимостью OpenAI API и CLI для работы с файлами проекта.

**Экспериментальный проект на частном протоколе.** Это независимый адаптер, не официальный API и не замена xAI API. Изменения сервиса могут нарушить работу. Используется ваша сессия и её квота; отдельные ключи OpenAI/xAI для режима `agent` не нужны. Native-режим проверяется на протокольных фикстурах; его работа с живым сервисом для этой публикации не подтверждена.

## Возможности

- Текстовые Chat Completions и Responses, JSON/SSE, история Responses в памяти процесса.
- Эмуляция function calling с проверкой аргументов и JSON Schema; функции выполняет клиент.
- Ограниченная очередь запросов, отмена, очистка временных агентов и явное раскрытие неподдерживаемых параметров.
- CLI для чтения файлов и подготовки изменений; запись требует `--apply` или применения сохранённого отчёта.
- Офлайн-проверки протокола, совместимости SDK, авторизации, очереди и файловых операций.

В режиме `agent` роли, функции и структурированные ответы задаются инструкциями модели. Это не constrained decoding: модель может нарушить формат. `temperature` и лимит токенов в этом режиме не управляют генерацией. Images, Audio, Embeddings и полный набор OpenAI API не реализованы.

## Быстрый запуск

Windows и Node.js 22 или 24. Для реальных запросов нужен установленный Grok Bot с выполненным входом под тем же пользователем Windows.

```powershell
git clone https://github.com/rcancer78-create/grokbot.git
cd grokbot
npm ci

# Новый случайный пароль локального сервера, только для текущего процесса.
$env:GROKBOT_TOKEN = node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))"
$env:GROKBOT_HOST = '127.0.0.1'
$env:GROKBOT_MODE = 'agent'
npm start
```

Сервер работает в текущем терминале. Для остановки нажмите Ctrl+C и дождитесь завершения очистки.

Настройки клиента:

| Поле | Значение |
| --- | --- |
| Base URL | `http://127.0.0.1:8788/v1` |
| Model | `grok-bot` |
| API key | Значение `GROKBOT_TOKEN` из сеанса запуска сервера |

Этот пароль защищает локальный сервер и отличается от токена сессии Grok Bot. По умолчанию профиль читается из `%APPDATA%\Grok Bot`; расшифровка DPAPI требует соответствующей учётной записи Windows. Вход и обновление сессии выполняются официальным приложением. Сервер рассчитан на одного владельца: клиенты с общим паролем получают доступ к общей истории Responses.

## Работа с проектом

По умолчанию CLI готовит изменения и отчёт без записи в исходные файлы:

```powershell
node project.mjs --root 'C:\path\to\project' --prompt 'Найди причину ошибки и предложи исправление'
```

CLI может сам запустить временный локальный сервер. Для записи используйте `--apply`; подробности, применение отчёта и запуск собственной команды проверки описаны в [техническом руководстве](docs/technical-details.md#работа-с-проектом-на-диске).

Прочитанные файлы передаются Grok Bot как результаты функций. Исключения для секретных файлов не являются универсальным детектором секретов. Отчёты в `.grokbot-runs` содержат исходный и изменённый код — проверяйте их перед передачей кому-либо. Используйте копию проекта или систему контроля версий.

## Офлайн-проверки

`npm test` запускает Node test runner с подставными транспортами и локальными HTTP-серверами. Установка Grok Bot и реальные credentials для этого не нужны.

Для дополнительной изоляции задайте несуществующий профиль в отдельном PowerShell-сеансе:

```powershell
$env:GROK_BOT_ROOT = Join-Path $env:TEMP ('grokbot-no-profile-' + [guid]::NewGuid().ToString('N'))
npm test
```

Windows CI выполняет `npm ci` и полный `npm test` на Node.js 22 и 24 с коротким временным путём и изолированным профилем. Офлайн-тесты не подтверждают текущую доступность сервиса или работу IDE целиком. Зафиксированные SDK-зависимости: `@ai-sdk/openai-compatible` 3.x, интерфейсы `@ai-sdk/provider` 4.x и OpenAI JS SDK 7.x.

`npm run smoke` и скрипты с `--live` обращаются к настоящему сервису и расходуют квоту; CI их не запускает. Живые сценарии этой публикации повторно не проверялись.
